# Local verification and prepared CI

Run `py -3.11 scripts/verify_repository.py` on Windows or `python3.11 scripts/verify_repository.py` on POSIX from the repository root. The script requires exact CPython 3.11.9 and runs child commands through `sys.executable` with argv arrays and no shell. Unit tests have a 60-second command limit; each CLI process has 20 seconds. It does not install or contact a model/service. The supported test suite itself uses bounded local SQLite/process fixtures. The outer command timeout kills its direct child; it is not a descendant containment mechanism.

The script executes the existing 44 meaningful tests, a fresh asserting demo/audit, preservation of an existing workspace (expected exit 2), and separate native approval/rejection CLI journeys. It gates pending exit 3 and denied/replay/rejected exit 4 explicitly. Direct read-only SQLite queries inspect all three tickets, request state and ordered audit before/after operator action and at final state. The approval must leave the ticket unchanged until resume and cause exactly one local mutation/CONSUMED grant; rejection causes zero mutation and refuses subsequent approve/resume. Audit export must equal stored observations.

Each unique ignored `work/verification/<UTC-and-UUID>/` run contains `receipt.json`, per-command raw stdout/stderr, exact argv/cwd/interpreter, Python/SQLite/platform versions, exit/time/timeout results and SHA-256 manifests before/after. Source hashes cover root files and application/tests/examples/scripts/docs/workflow; generated work/Git/cache are excluded. Hashes identify the files observed in that run, not authorship or a signature. Original M1/M2 scratch receipts are copied byte-for-byte into `prior_receipts/` before tests rewrite them; fresh receipts are copied into `fresh_process_receipts/`. Receipt JSON hashes output and each preserved raw receipt. No failure is silently turned into a pass. The script prints test output and final receipt location; CI runner-local receipts are not uploaded or claimed as permanent hosted artifacts.

`scripts/manual_operator.ps1` is the separately executed documented local operator journey. It checks native exits, prints the stored review and explicitly approves that fingerprint before immediate resume. `commands.json`/raw files persist command evidence, and a final receipt captures interpreter/source hashes and response assertions. The runtime probe was corrected to `json.dumps(dict(...))` so Windows PowerShell's native argument handling cannot remove quoted JSON key literals. The corrected journey passed once in Windows PowerShell **5.1.26100.9444** and once in PowerShell **7.6.5**, each launched natively from PowerShell 7 with `-NoProfile -File scripts/manual_operator.ps1`. Read-only SQL confirmed resolved/version 2, CONSUMED, one mutation audit, nine ordered rows and refused replay in both fresh workspaces. Actual shell executables/argv/effective module paths and source hashes are retained in the correction evidence.

A first Python-launched Windows PowerShell preflight passed the corrected runtime probe but failed to find `Get-FileHash`, before any authority CLI action. A read-only diagnostic observed that this launcher passed the PowerShell 7 module paths into Windows PowerShell; the passing native launch used Windows PowerShell module paths. This failed attempt and main's original quote-related failure are preserved. These observations qualify the tested shell environments; the assigned correction changes only the runtime probe, without altering environment or hashing behavior. These are safe scripted operator simulations; there is no evidence of enterprise authentication or human approval study. POSIX manual commands are documented but unexecuted locally.

The prepared workflow uses Windows 2025 and Ubuntu 24.04 x64, at most two jobs, five minutes each, fail-fast false, read-only contents token and checkout without persisted credentials or global safe-directory writes. It has no custom secrets, package install, deployment or publication step; setup may fetch the pinned interpreter. Public standard hosted runners are the intended free CI path, consistent with [GitHub's billing documentation](https://docs.github.com/en/billing/concepts/product-billing/github-actions), read 2026-10-08.
